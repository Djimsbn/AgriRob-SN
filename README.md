# AgriRob-SN

**Kinematic and dynamic modelling of a six-degree-of-freedom agricultural
manipulator for smallholder food crops in Senegal**

This repository contains the complete source code, simulation results and
figure scripts of the paper:

> [Authors]. *Kinematic and dynamic modelling of a six-degree-of-freedom
> manipulator for smallholder food crops in Senegal: control robustness and
> energy analysis on Sahelian sandy soils.* Submitted to *Computers and
> Electronics in Agriculture*.

Every figure, table and number quoted in the paper is regenerated by the code
below. No result is typed by hand: `make_macros.py` writes each value into a
LaTeX macro file that the manuscript imports.

## Contents

| File | Role |
|---|---|
| `agrirob_model.py` | Robot model: modified Denavit–Hartenberg forward kinematics, geometric Jacobian, damped-least-squares inverse kinematics, Lagrangian dynamics (M, C, G, friction), Bekker–Wong-derived locomotion model |
| `simulate_control.py` | Sampled-data simulation of three control laws (computed torque, PD + gravity, PD alone), optional unmodelled payload |
| `ik_statistics.py` | Inverse-kinematics convergence statistics (500 random targets, warm start) |
| `energy_budget.py` | Locomotion power across soils, arm-power bracket, endurance, solar contribution |
| `figure_1_kinematics.py` | Figure 1 — kinematic diagram |
| `figure_2_workspace.py` | Figure 2 — reachable workspace |
| `figures_3_to_7.py` | Figures 3–7, drawn from the result files |
| `make_macros.py` | Writes `latex/results_macros.tex` and the control-comparison tables |
| `paths.py` | Repository-relative paths |
| `run_all.sh` | Runs the whole pipeline |
| `results/` | Pre-computed simulation outputs (JSON summaries, NumPy time series) |
| `figures/` | Generated figures (PDF and PNG) |
| `latex/` | Generated LaTeX macros and tables |

## Installation

Python 3.10 or later.

```bash
git clone https://github.com/<user>/agrirob-sn.git
cd agrirob-sn
pip install -r requirements.txt
```

## Reproducing the results

**Figures and numbers from the pre-computed results** (about 1 minute):

```bash
python3 ik_statistics.py
python3 energy_budget.py
python3 figure_1_kinematics.py
python3 figure_2_workspace.py
python3 figures_3_to_7.py
python3 make_macros.py
```

**Everything from scratch**, including the 13 dynamic simulations (about
35 minutes on a single core):

```bash
bash run_all.sh
```

A single simulation:

```bash
python3 simulate_control.py <law> <Tc_ms> <n_sub> [payload_kg]
#   law        ct (computed torque) | pdg (PD + gravity) | pd (PD alone)
#   Tc_ms      control period in ms (5 = 200 Hz)
#   n_sub      RK4 integration sub-steps per control period (5 -> h = 1 ms)
#   payload_kg unmodelled payload added to link 6 (default 0)
python3 simulate_control.py ct 5 5 1
```

Random seeds are fixed; results are exactly reproducible.

## Key results

Tomato-picking motion, 0.30 m in 4 s, control at 200 Hz, RK4 at 1 ms.

| Unmodelled payload | Computed torque | PD + gravity | PD alone |
|---|---|---|---|
| 0 kg | < 0.02 mm | 1.53 mm | 37.73 mm |
| 0.5 kg | 8.44 mm | 6.33 mm | 39.79 mm |
| 1 kg | 15.12 mm | 12.40 mm | 42.02 mm |
| 2 kg | 25.44 mm | 21.48 mm | 46.44 mm |

RMS Cartesian tracking error. With an exact model, computed torque tracks the
reference to within the integration resolution, as theory predicts. With an
unmodelled payload, PD with gravity compensation is 18–33 % more accurate.

- Locomotion on wet sandy soil draws at least **2.28 times** the power needed
  on asphalt (a lower bound; see the paper).
- On Dior soil with a 10 kg payload, a 1.5 kWh battery meets a 4 h endurance
  target below **0.56–0.67 m/s**, depending on the bound on arm power.
- Inverse kinematics from a fixed cold start converges for **44.2 %** (full
  pose) and **80.0 %** (position only) of 500 targets, and at **801/801**
  steps when warm-started along the trajectory.

## A note on numerical integration

The wrist links have inertias down to 1e-3 kg m², giving time constants of
about 2 ms. The control law is therefore evaluated at 200 Hz while the plant is
integrated with RK4 at 1 ms. Integrating at the control period (5 ms) produces
a spurious tracking error of several millimetres; see Section 6.3 of the
paper. `python3 simulate_control.py ct 5 10` runs the 0.5 ms convergence check.
